# 原理与排障

## 工作方式

仓库把原本需要完整桌面环境的 aTrust 拆成三层：

1. Apple Container 提供轻量 Linux ARM64 运行环境和 TUN 网络能力。
2. Rust supervisor 调用 aTrust SDK，管理登录、短信验证、Core、Xtunnel 和 SOCKS5 生命周期。
3. FlClash 的 `校园网.yaml` 把本机流量统一转给 `127.0.0.1:11080`。

只有 aTrust 隧道真正连通后，SOCKS5 数据面才可用。停止脚本会先通知 supervisor 断开，再停止容器；不会切换或改写 FlClash 配置。

## 为什么镜像仍然需要官方安装包

仓库只提供编排、兼容和裁剪逻辑。构建时会从用户提供的官方 ARM64 `.deb` 中提取必要文件，然后：

- 去除桌面 UI、Electron 资源和无关组件；
- 补齐 aTrust 运行所需的 Linux 动态库；
- 使用系统 `libstdc++`，避免官方旧版本缺少新 `GLIBCXX` 符号；
- 加入 `fake-getlogin` 兼容层；
- 编译 supervisor，最终生成 scratch 运行镜像。

官方安装包只作为本地构建输入，不会进入 Git 仓库。

## 端口

| 地址 | 用途 |
| --- | --- |
| `127.0.0.1:11080` | 给 FlClash 使用的 SOCKS5 出口 |
| `127.0.0.1:54680` | 启停脚本使用的本机辅助接口 |

两个端口都只监听回环地址。

## 常见问题

### 提示找不到 `container`

Apple Container 尚未安装，或终端找不到它。先确认：

```bash
container --version
container system status
```

### 提示找不到镜像

先用官方 ARM64 `.deb` 构建一次：

```bash
./scripts/build-apple-arm64.sh /path/to/aTrustInstaller_arm64.deb
```

### 登录成功但网页打不开

按顺序检查：

1. 启动窗口是否显示“连接成功”。
2. FlClash 是否切换到 `校园网.yaml`。
3. `校园网.yaml` 中端口是否仍为 `11080`。
4. 目标是否确实需要该机构的 aTrust 网络权限。

可以直接测试 SOCKS5：

```bash
curl --socks5-hostname 127.0.0.1:11080 -I https://目标网址
```

### 切换到校园网后 ChatGPT 失联

这是全局转发配置的预期结果：所有流量都会改走校园网。完成校内访问后，先把 FlClash 切回日常代理配置，再停止 aTrust Lite。

### Apple Container 占用空间较大

本项目镜像本身经过裁剪，但 Apple Container 的虚拟机、基础镜像和构建缓存仍会占用磁盘。可用以下命令查看：

```bash
container image list
container builder status
```

清理前先确认没有仍需保留的其他镜像；不要在不了解影响时删除 Apple Container 的整个数据目录。

## 已知限制

- 只验证了 Apple Silicon 和 ARM64 aTrust 安装包。
- 不同学校或机构可能使用不同认证流程，首次使用仍需实测。
- 依赖 aTrust 的内部 SDK 行为，官方升级可能造成兼容性变化。
- 当前配置是全局出口，不做网站分流；这是为“临时专用”场景做的取舍。
